# Greenfield agentic project checklist (how this repo is set up)

The repo is as easy for agents to work in as for humans, and hamonn dogfoods itself.

1. `AGENTS.md` at the root (`CLAUDE.md` symlinks to it): purpose, layout, commands, rules, forbidden actions (< 150 lines).
2. `docs/repo-map.md` regenerated by `pnpm repo:map`.
3. ADRs in `docs/adr/` (001 language, 002 ports/adapters, 003 fork-per-lane, 004 landing engine, 005 per-lane ledger).
4. Spec before code: `docs/spec.md` is the source of truth; PRs link the section they implement.
5. One command each: `pnpm build:wasm | test | test:one <path> | lint | typecheck | check | dev | deploy`.
6. lefthook: biome + rustfmt pre-commit, `pnpm check` pre-push (installed by `prepare`).
7. Tests first, small PRs (≤ 400 lines), conventional commits, a changeset per user-visible change.
8. Deterministic fakes, no network in unit tests; contract suites for every adapter.
9. Structured JSON logs (`{level, event, laneId, projectName}`); Worker `observability.enabled`.
10. No secrets in the repo; `.dev.vars.example` documents every variable; gitleaks in CI.
11. Defect telemetry: `fix:` commits carry `Detected-by:` / `Introduced-in:` trailers.
12. Dogfood: register this repo as a hamonn project (`laneMode: "branch"`, GitHub adapter) and have agents open lanes on it.
13. Issue templates include `adapter-request.yml` with the verb checklist.
14. `docs/plans/` holds one file per sprint with status lines updated at the end of each session.
